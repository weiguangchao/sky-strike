# Phaser 4 二维运行架构

运行时使用 Phaser 4.2.1。战场、机库和图鉴均显示二维精灵，浏览器不加载 Three.js 或 GLB；支持章节战役与无尽波组、空海分层、半径为6的中心判定、舰船部件破坏、强化、存档和窗口适配。

## 职责

- `game/engine.ts` 保留独立战斗模拟，接收秒为单位的时间步和领域输入，输出完整事件；不依赖 Phaser、DOM 或纹理。已有固定随机种子的完整通关测试继续约束战斗规则。
- `game/runtime.ts` 创建 Phaser Game 和 battlefield Scene，场景在全部基础精灵就绪后调用战斗帧回调。Phaser 管理帧循环、键盘、鼠标和触摸，既有相对拖动倍率及移动边界保持一致。
- `game/render.ts` 创建海面、岛屿、尾流、舰船、飞机、弹药、爆炸、补给、判定点与敌弹显示层。Phaser Image 对象池复用精灵；部件切换完好／残骸图层，Phaser 粒子与补间表现战斗事件。
- `game/sprites.ts` 复用 Phaser Loader、纹理缓存和进行中的下载，下载失败清除待处理记录以便重试。机库和图鉴将缓存中的同一PNG绘制到 Canvas 2D。
- `game/main.ts` 负责可访问的DOM界面、存档、战斗事件与音效协调，不再拥有 requestAnimationFrame 游戏循环。页面隐藏或窗口失焦时自动暂停并清理输入；VisualViewport变化后同步Phaser的画布坐标边界与输入比例。

## 时间、坐标和状态

模拟时间单位为秒，Phaser传入的毫秒转换后最多推进0.05秒。战斗、触摸与HUD仍使用480×760逻辑坐标；240×380固定画布的根容器缩小为0.5倍。进入战斗、返回机库、全屏和可视区域变化后更新画布边界。

暂停、强化和结算时模拟不推进，粒子与补间一并冻结；DOM操作继续可用。重开与返回机库会清理旧特效。减弱动态效果时减少装饰动画、受击闪烁和震屏。键盘边界对同一原生事件只处理一次，避免Phaser在一帧内重放队列时重复投弹。

## 资源与发布

基础26项PNG在启动时下载，历史舰艇、飞机和潜艇按需下载。历史预览使用请求序号丢弃迟到结果，加载失败后可重新打开条目。游戏读取本机已保存的舰船外观，舰船与残骸使用生成时的外观。

离线生成、指纹和图层约定见[模型与精灵流程](models.md)。构建校验清单后打包，移除仅供开发的GLB目录；部署保持纯静态资源。此迁移不自动发布到现有线上环境。
