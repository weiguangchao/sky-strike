# Blender 模型流程

## 资源位置

百年舰机新增独立的 `century-archive.blend`、`century-archive.json`、`scripts/blender/build_archive.py` 和20个 `archive-*.glb`；原有168个战斗／历史GLB保持独立。`npm run models:build` 重建两库，`npm run models:build:archive` 只重建新增库。新资源和逐模型双 GPT Sol ≥9.8 验收详见[百年舰机](century-archive.md)；当前全球服役目录尚未穷尽。

新增型号的独立截面与轮廓在 `game/archive-profiles.ts`，随条目一起序列化给 Blender；翼根接合、中央翼段、框式座舱、现代圆钝艇艏、旧艇艉舵和围壳潜舵均使用实际实体几何。模型测试读取导出的GLB验证结构接合，不能仅以元数据计数代替外形检查。

- 可编辑模型库：[sky-strike-ww2.blend](../../assets/blender/sky-strike-ww2.blend)。各资产保存在独立集合中，工作文件按网格排列，方便检查与修改。
- 建模与导出脚本：[build_models.py](../../scripts/blender/build_models.py)。使用 Blender Python API 创建几何体、材质、中队标记与螺旋桨节点。
- TypeScript 执行入口：[models.ts](../../scripts/models.ts)。负责寻找并启动 Blender。
- 历史舰艇定义：[naval-history.ts](../../game/naval-history.ts)，含148个条目、史料与布局。执行入口先生成 [historical-fleet.json](../../assets/blender/historical-fleet.json)，Blender 与战场部件映射使用同一组数据。
- 游戏模型：`game/public/assets/models/*.glb`。导出清单 `manifest.json` 记录生成器版本、文件名、面数和字节数。
- 运行时加载器：`game/models.ts`，渲染入口：`game/render.ts`。

## 重新生成

```sh
npm run models:build
```

macOS 默认使用 `/Applications/Blender.app/Contents/MacOS/Blender`；其他平台从 PATH 寻找 `blender`。也可显式指定：

```sh
BLENDER_PATH=/path/to/blender npm run models:build
```

该命令会从脚本重新生成 `.blend` 与 GLB；手工修改 `.blend` 后，应先把需要保留的修改同步到生成脚本，或单独按相同坐标和文件名导出，再决定是否运行生成命令。

## 坐标、动画与性能

- Blender 使用 X 为翼展、+Y 为机首、+Z 为上方；glTF 转换为 X 翼展、−Z 机首、+Y 朝上。
- 导出各模型时原点位于中心。工作文件中用于排列模型的位置不写入游戏导出。
- 螺旋桨父节点命名为 `propeller_00` 等；运行时绕局部 Z 轴旋转，保留真正的 3D 叶片。
- 每个父节点内合并静态几何，保留部件、炮塔与螺旋桨父节点。模型实例共享几何和材质，飞机、舰船和沉没残骸使用对象池。
- 舰船 `part_*` 与 `ruin_*` 空节点分别保存自定义属性 `game_part`／`game_ruin`，值为 `aa-port`、`aa-starboard`、`bridge` 或 `flight-deck`。启用 glTF extras 导出，运行时按 `userData` 绑定独立完好部件与焦黑残骸，不依赖 Blender 自动编号或 Three.js 清理后的节点名。
- 图鉴主炮保留前后／向外舷侧起始姿态，背负式炮塔有独立支撑炮座，炮管避开相邻炮塔与舰桥。战场中轴主炮朝左舷、两舷炮各朝舰外进行对海演出，`turret_aa_*` 节点跟随对空方向，副炮保留原始姿态。甲板部件包含起飞区、阻拦索和停机，毁坏后隐藏，舰体仍可直接受伤。
- 合并静态网格后在 Blender 应用旋转与缩放，使导出节点的变换与几何尺寸一致。
- 子弹、补给、火焰与烟尘采用实例化绘制；战场固定 240 × 380、机库预览固定 160 × 100、作战单位与历史图鉴 192 × 120，像素比为 1，关闭抗锯齿并使用 CSS 像素缩放，保留 Blender 资产的 3D 结构。
- 顶视正交投影与 480 × 760 逻辑坐标一致，视觉上的高度与倾斜不改变受击判定。战场将舰船垂直比例压缩到50%，并按根节点 `combat_stretch` 放宽舰体以适配原单位范围；图鉴保留原始比例。部件原点与战场攻击目标坐标同步，碰撞算法、半径和战斗数值保持原规则。
- 根节点还保存 `historic_id`、`historic_year`、`game_role`；舰船在生成时锁定所选原型，沉没残骸继续使用该模型。选用同一原型时共享几何和材质。
- 航母烟囱与舰岛侧布置相连，保留赤城等向舷外下弯烟道和信浓向外倾斜烟囱；直通甲板中线不放烟囱。贝尔法斯特与悉尼的弹射器为舰中部横向轨道，艉部航空区与舰艏航空区按原型分别布置。
- 舰船采用 `fleet_*` 海军色板：深色舰壳、灰绿舷缘与金属甲板、旧木甲板、浅色钢制屋顶、暗色舱口与克制的锈蚀。采用多层收束船型、倒角炮塔和舰桥，避免整块亮白或矩形平板。
- 木甲板的稀疏纵缝高于甲板表面，保持低分辨率下可见的层次。两艘航母的停机与防空炮位、艉部升降机错开，机翼、尾翼和机身加粗；友军航母保留独立的左侧停机带和中央玩家滑跑通道。
- 舰船根节点保存归一化 `waterline_beam`／`waterline_length`，运行时按实例缩放绘制贴合真实船体的艏浪和尾流；这组尺寸只用于表现，不更改玩法碰撞框。
- 舰船导出省略法线，由 Three.js 的标准 glTF 缺省法线路径生成平面明暗，保留低多边形切面并减少重复顶点与载荷；飞机、道具和敌弹保留原有法线及材质，未增加运行时解码器或外部依赖。
- 图鉴按可见网格顶点在相机坐标中的投影取景，舰船使用斜向三分之四视角和完整比例，保留 12% 取景余量；不把隐藏残骸或旋转后的轴对齐包围盒计入留白。
- 模型完全本地化，GLB 内嵌几何与材质，不从外部网址加载模型或纹理。
- 道具与敌弹的 `signal_*` 材质在 Blender 中使用纯颜色输出节点，导出为 `KHR_materials_unlit`；运行时关闭 tone mapping，避免曝光、日光和电影色调映射把辨识色冲淡。
- 道具与敌弹直接使用这些 GLB 的几何与符号，按材质拆成共享实例批次，不为每个掉落物创建独立的模型绘制调用。
- 实例矩阵每帧只上传当前使用的前缀，空批次不上传，避免低端手机反复传输整个预分配缓冲。

## 验证

模型库共188个GLB：基础26项、按需加载的142项旧舰库外观，以及20项百年飞机／潜艇；资料共覆盖168条。测试限制单模型小于400KB、基础启动库小于2.5MB、旧档案小于17MB、新增首批小于4MB、两库合计小于21MB。查看或选用条目时才加载相应本地GLB，不在启动时加载全部档案。

`npm test` 检查 GLB 格式、几何数据、螺旋桨节点、可拆部件与残骸属性、水线尺寸、舰船高度、停机机翼朝向及炮位间距、木甲板接缝的顶视可见性、导出原点、资源体积和识别色；`npm run test:e2e` 检查浏览器中模型载入、WebGL、完整流程，以及实际像素中的道具和敌弹颜色。

美国扩充舰级的数据在 [us-fleet.ts](../../game/us-fleet.ts)，完整范围、模型外观与来源见[美国舰级库](us-fleet.md)。现代航母的停机为喷气外形，斜角着舰区、升降机与弹射轨道单独建模；导弹发射器以 `naval_launcher` 属性区分，舰级根节点保留 `naval_class`。

航母升降机保留 `naval_lift` 分组以核对实际平台的左右舷及前后位置；烟囱的 `funnelCant` 为建模外倾参数，肯尼迪 CV-67 按此参数创建带实际网格的倾斜烟道。
