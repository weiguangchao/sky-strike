# Blender 模型流程

第20轮新增C-54G四发运输机与C-119C双尾撑运输机，均使用收起的前三点起落架。发动机数量绑定相应短舱元组，常规尾翼／双尾撑、尾轮／收起前三点、全包／半露主轮分别以判别联合表示。真实GLB回归量测长度、翼展、翼面积，以及发动机、桨轴、尾撑和平尾的实体接合；窗面投影到真实机身。本轮已按Grok优先顺序完成三席验收，三席总评及全部176项均≥9.8，最终审计176项通过。目录完整性仍在核对。

## 重新生成

```sh
npm run models:build
```

macOS 默认使用 `/Applications/Blender.app/Contents/MacOS/Blender`；其他平台从 PATH 寻找 `blender`。也可显式指定：

```sh
BLENDER_PATH=/path/to/blender npm run models:build
```

该命令会从脚本重新生成 `.blend` 与 GLB；手工修改 `.blend` 后，应先把需要保留的修改同步到生成脚本，或单独按相同坐标和文件名导出，再决定是否运行生成命令。

## 二维精灵生成与运行时

```sh
npm run sprites:build
npm run sprites:check
```

`sprites:build` 从当前184个本地 GLB 读取几何，使用 TypeScript 离线正交栅格器生成 PNG，不需要 WebGL、浏览器或 Blender 进程。Three.js 只作为离线几何解析和源模型测试的开发依赖，浏览器运行时使用 Phaser 4.2.1。

- `scripts/sprites.ts` 是可复现生成入口。源 GLB、源模型评分与 Blender 文件保持独立；更新源模型后必须重新生成精灵。
- 每项资产含顶视 `top` 与斜向 `preview`；舰船另含 `part:<id>` 完好部件和 `ruin:<id>` 损毁部件。友军航母不参与损毁，不要求残骸。
- 按 `game_part`／`game_ruin` 的祖先节点拆分网格，按高度排序图层。透明精灵裁到实际像素边界，并保留相对于模型原点的锚点与世界尺寸，再以留白间隔打包到每型号一张 PNG，避免将大量透明区域传入 GPU。
- 顶视保持 glTF 的 X 为横向、−Z 为机首；二维图像的 Y 向下。战场使用模型 ID、舰种缩放及 `combat_stretch`，与既有部件目标坐标一致，碰撞和数值不变。
- 图鉴预览使用离线斜向投影，船舶和潜艇从舰艉左下向舰艏右上展开；按实际像素边界适配 192×120，保留12%留白。机库为160×100。预览用 Canvas 2D 绘制同一张已加载 PNG，不额外创建 WebGL 上下文。
- 战场固定240×380帧缓冲，Phaser 根容器以0.5倍呈现480×760逻辑坐标。关闭抗锯齿并采用最近邻采样，CSS像素放大，DPR不改变内部栅格。
- `game/sprite-manifest.json` 记录每项源 GLB、输出 PNG 和生成器的 SHA-256、文件体积、帧边界、锚点、尺寸、舰体横向比例与螺旋桨位置。
- `game/models.ts` 只保留资产ID与映射；`game/sprites.ts` 使用 Phaser Loader 下载本地 PNG，缓存纹理并注册裁剪帧；`game/render.ts` 使用精灵池绘制舰机、部件、残骸、弹药与补给，使用 Phaser 粒子和补间绘制爆炸及冲击波。
- 螺旋桨采用二维闪动叶片，舰船损毁切换局部图层，沉没通过侧倾与透明度表现。减弱动态效果模式关闭装饰晃动和震屏。历史舰船在生成时锁定外观，残骸继续使用相同资产。
- 识别标记保留源 `signal_*` unlit 材质的精确颜色和形状。浏览器不进行灯光或色调映射；敌弹位于烟尘、补给和玩家判定点上方。
- 浏览器只请求 `game/public/assets/sprites/*.png`。原 GLB 保留于仓库供离线生成与几何验证，生产构建移除 `dist/assets/models/`。

CG-4A采用独立箱形货舱截面、无动力高翼、四根接入实体机翼的撑杆、关闭的开启式机首接缝及三组固定起落架。七型斜角甲板航母的损毁甲板片下移并接入保留甲板；自动检查排除战斗中会消失的完好作业层，验证残骸确有支撑。第10、11轮均未通过最终验收，第12轮修复后重新送审。

## 源模型约定

Blender 保持 X为翼展、+Y为机首、+Z向上；GLB原点位于中心。螺旋桨节点、可拆部件和残骸 extras、炮塔与水线属性继续保留，供离线精灵和源模型验证使用。舰船外形、历史舰炮／烟囱／升降机、飞机截面与翼面等规则继续通过已有GLB几何检查，源文件和建模脚本均保留。

原始GLB的三分之四、顶视、侧视和前视审阅工具保留在 `scripts/archive-views.ts`，仅用于开发环境中的源模型评审；产品入口不引用它。二维视图工具为 `scripts/sprite-views.ts`。

源模型继续保留炮塔起始方向与间距、独立防空炮／舰桥／甲板节点、螺旋桨父节点、归一化水线尺寸和导出中心原点。`naval_lift` 区分各升降机，`naval_launcher` 区分导弹发射器，`naval_class` 保留舰级，肯尼迪 CV-67 的 `funnelCant` 保留实体外倾烟道。

## 验证

`npm run sprites:check` 检查184项精灵与源文件、生成器及PNG指纹一致，所有帧在图集内、像素非空、完好部件具有残骸（友军航母除外）。每PNG小于100KB、基础26项小于600KB、全库小于4MB。

`npm test` 继续检查原始 GLB 格式、实体几何、节点、识别色和源模型体积，并加入精灵完整性检查。`npm run test:e2e` 检查全部舰机二维预览、Phaser版本、无GLB网络请求、按需加载与失败重试、完整战役及真实像素中的敌弹／补给和HUD透视性。

当前全库176个载具的重建评分同时绑定源几何与最终PNG，先由Cursor Grok 4.7 xhigh独立评审，总评和全部模型评分均≥9.8后，再由GPT Sol xhigh和Claude Opus high同轮总评与逐项评分均≥9.8。旧评分仅作历史记录，当前状态以 `game/model-reviews.json` 为准。几何四视图与实际二维视图均供评审检查。

## 全库载具重建

- 当前范围为176个载具：29架飞机、129艘水面舰船及18艘潜艇；另8项场景、补给与敌弹保持原有用途。
- `refine_geometry.py` 共享纵向连续截面、结构倒角与有厚度的扭转螺旋桨叶片。飞机使用连续机身和实体翼型，舰船具有分段舭部、甲板层级与炮口，潜艇采用更细的艇体截面、随艇体变化的甲板与独立推进器。
- 载具导出不携带未使用的UV坐标或法线，离线栅格器从实际三角面计算法线；本地材质色和实体几何决定精灵外观。战斗碰撞、移动和武器数值保持原有输入。
- 先执行 `npm run models:build`，再执行 `npm run sprites:build`。后者完成PNG生成后刷新绑定最终可见资源的版本指纹；未重新生成PNG的中间结果不能用于评审。
- 生成实际审阅板：`npx tsx scripts/model-evidence.ts`。审核范围与三方评分规则见[百年舰机](century-archive.md)。

### 第二轮造型与接合检查

三方首轮总评为 Claude Opus high 6.4／GPT Sol xhigh 8.0／Cursor Grok 4.7 xhigh 7.8；逐模型540条原始评分保留在 `game/model-reviews.json`，首轮没有模型达到三方9.8。后续模型修改使旧分数失效，不能借用首轮分数验收。

- 水面舰体按战列舰、巡洋舰、驱逐舰、航母、商船、巡逻舰、低干舷滑行艇和内倾穿浪舰体分别制作纵向站位。舰艏前倾／内倾、艉部收束、舭部和舷弧进入实际几何；上甲板按纵向条带闭合，避免非共面大多边形跨过舷弧。上层结构随甲板在高度方向接合，原有平面部件锚点与战斗判定不变。
- 移除统一的六枚舷窗和固定立柱。PT-109采用低矮舱体、开放风挡与机枪环；隐身舰不套用旧式封闭双联防空炮。烟囱增加实物口缘与内壁，原有数量、位置和烟道方向保留。
- 航母使用按舰宽缩放的舰岛及侧廊，作业区贴合飞行甲板。喷气航母区分早期平面阵列舰岛、桁架雷达舰岛和后置紧凑传感器舰岛；防御装备按所示年份处理，不能将“战后航母”一律当成无炮或一律添加晚期近防炮。[NHHC 的 Forrestal 记录](https://www.history.navy.mil/content/history/nhhc/research/histories/ship-histories/danfs/f/forrestal-cva-59.html)列有8门5英寸炮，本库保留1960年参考外形的8座单炮舷台。
- 短剑增加实体起落架支撑；俯冲机主翼增加内段下反、外段上反的高度折线。玄武使用收短的中央机舱、渐收双尾撑和双垂尾；轰炸机及甲板停机使用有轮廓的尾翼与连续机身。控制面、翼根与座舱口缘进一步分层。
- 潜艇甲板外壳和封闭围壳增加斜肩过渡，潜舵／艉舵采用实体翼型。弗吉尼亚的公开泵喷外导管保留中空结构并增加可读口缘，不补造内部推进器设计。
- `tests/models.test.ts` 从真实导出GLB量测倒海鸥翼的高度关系，并通过双向射线确认起落架支撑顶点进入闭合机翼体积。源模型图和最终192×120精灵仍分别提供三方审阅，自动化不代替评分。

### 第三轮结构修正与评审顺序

- 舰体高度按舰种调整，保留纵向轮廓与舷弧；只调整美术高度，不改变平面战斗部件锚点、碰撞或数值。朱姆沃尔特舰桥收进内倾甲板，机库门并入舰桥后部；其他现代舰后烟囱在相连甲板室上方完整露出，后部垂发单元保持可见。宙斯盾阵列贴在前后甲板室表面。
- 炮塔按海军及年代区分外壳轮廓与斜顶。分页塔桥增加贯通支撑，PT-109机枪环保持中空并连接枪架，圆烟囱与日本航母下弯烟道保留凹入口和实体口缘。现代与隐身舰移除统一的旧式救生艇和系缆柱排布。
- 航母停机增加与实际飞行甲板接触的起落架；轨道、标线和升降机贴合甲板。喷气停机避开斜角着舰区。中途岛1991年参考外形保留两条舰艏弹射轨道，依据[中途岛博物馆馆史](https://www.midway.org/blog/midway-leads-fight-during-operation-desert-storm)。
- 海达人1943年外观补上X位双联102毫米高射炮，A／B／Y位仍为三座双联120毫米主炮，依据[原舰武器系统说明](https://www.jproc.ca/sari/285_notes.html)。猫鲨级早期指挥台增加连续潜望镜支架。
- 从第三轮开始只提交Cursor Grok 4.7 xhigh首审；总评及180项当前版本评分均严格大于9.8，且 `npm run models:audit -- --require-grok` 通过后，再交给GPT Sol xhigh和Claude Opus high评审同一冻结版本。后两者逐模型仍须各≥9.8。修改模型后重新从Grok首审开始，不能沿用旧版本分数。

### 第四轮轮廓与表面

第三轮Grok总评9.4，逐模型9.2–9.7，未进入后两席评审。全部180条真实分数绑定第三轮版本，保留在评分记录中。

- 战时舰桥按海军、舰种和既有舰级定义区分实体轮廓：层叠指挥台、圆筒塔桥、锥形塔桥、装甲指挥塔和低矮开放桥分别制作连续截面与表面窗带；日本分页塔桥按舰级调整层级和收束。战后宙斯盾、隐身舰与喷气航母已确认的轮廓继续保留。美术轮廓按原生像素大小简化，不宣称工程尺寸级复原。
- 烟囱的截面比例、收束、倾斜、口缘和下部外罩随舰种／年代变化。救生艇缩小为中空艇壳、座板或机动艇舱，并连接吊架；甲板系缆设备使用低矮双柱和小艇缆桩，避免重复的大圆柱排布。
- 飞机垂尾和旧式潜艇舵面采用有厚度的对称翼型，保留既有外缘。架空侦察机使用较窄主翼、细机身和后移短座舱；双发重型飞机增加前部观察舱。现代潜艇用更深艇壳与较亮围壳区分体块，保留公开外部推进结构。
- 原有战斗数值、平面部件位置、主炮／副炮／烟囱数量与舰岛侧别保持不变。每轮仍须验证完整GLB、分层PNG、实际图鉴尺寸、炮管净空、甲板接触和浏览器交互。

### 第五轮原生尺寸辨识

第四轮Grok总评9.5、逐模型最高9.7，未进入GPT／Claude评审。第五轮集中调整早期驱逐舰和美国炮巡洋舰的舰桥体块：早期开放桥、领舰高桥、紧凑式舰桥、圆前缘桥和日法驱逐舰层级分别处理，加入较深下层与较亮上层的体块分界。侧向占地仍处在原有部件范围内，姊妹舰不为增加像素差异而添加虚构装备。
