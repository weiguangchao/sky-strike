# 产品特点与画风

## 产品特点

- **二战题材的竖版空战**：驾驶螺旋桨飞机，以中心判定穿越弹幕，面对战斗机编队和重型轰炸机。
- **单局肉鸽成长**：通过随机三选一改装构筑散射、僚机、追踪火箭、暴击与防御组合，每局重新成长。
- **三种战机手感**：游隼的均衡性能、雨燕的高速机动、玄武的双发重装提供不同取舍。
- **完整战役循环**：两个航区、10 波攻势、两场首领战，有失败、胜利、结算与重开。
- **真正的 3D 模型**：Blender 制作飞机、舰船与海岛，Three.js 在浏览器实时渲染；保留可编辑源文件和生成脚本。
- **TypeScript 开发**：战斗、渲染、输入、音效、模型加载和项目配置具有类型约束，构建前运行严格类型检查。
- **电脑与手机直接游玩**：键盘、鼠标、触摸操作，适应窗口且无页面滚动，保存本机纪录。

## 整体视觉方向

采用 **二战复古航空** 风格，以 1944 年太平洋战场为氛围参考，表现架空中队和海域作战。飞机形制、海岛营房、航母、界面与武器命名保持一致；肉鸽改装属于游戏化设计，不宣称严格历史复原。

### 色板与材质

| 用途 | 方向 |
| --- | --- |
| 界面底色 | `#081b29` 深海蓝，明确衬托战场与文字 |
| 仪表／面板 | `#153348` 海军蓝，避免整页灰绿混在一起 |
| 标题／按钮 | `#f7f1df` 明亮象牙白与 `#f5c568` 黄铜金 |
| 升级补给 | `#35dfff` 青蓝，方箱与箭纹 |
| 维修补给 | `#38e68f` 鲜绿，八角外框与十字 |
| 航弹补给 | `#a38bff` 紫色，菱形外框与航弹符号 |
| 敌弹 | `#ff384b` 红色圆弹、`#ff4d8b` 玫红尖弹 |
| 战场 | 深蓝海面、金色沙岸、饱满橄榄迷彩与绿色植被 |

机体使用橄榄迷彩、海军蓝、旧铝和黄铜色，座舱采用青色玻璃。使用中性天空补光和明确日光，保留暗部与高光；海面按独立蓝色色板输出，避免暖色泛光或灰雾覆盖。飞机与舰船保持二战造型；战斗标记使用更鲜明的游戏识别色，优先确保可读性。

### 模型与场景

- 玩家战机有螺旋桨、机翼、副翼、尾翼、座舱框架、机炮与中队标记，玄武为双发双尾撑机型。
- 首领为多发重型轰炸机，带玻璃机首、炮塔与多组真实旋转的螺旋桨。
- 航母包含木质甲板、跑道线、阻拦索、停机、舰桥和防空设施。
- 海岛包含沙滩、分层地形、棕榈树、道路与营房；海面具有连续细波纹。
- 使用顶视正交投影保持瞄准与碰撞一致，机库预览使用倾斜相机展示 3D 机身。

### 战斗表现

- 机炮为细长金白曳光弹；敌弹为小型红色圆弹或玫红尖弹，带深色轮廓、亮色细边与少量亮点，提高深海和色弱视角中的辨识度。
- 补给同时用颜色、明显更大的外形、白色边框及中心符号区分：青蓝方箱箭纹用于升级，绿色八角十字包用于维修，紫色菱形航弹箱用于补充航弹。不能仅靠颜色区分，灰度画面也应可辨。
- 这些标记由 Blender 建模并输出 `KHR_materials_unlit`，运行时关闭标记的 tone mapping，使识别色不受场景日光或曝光变化影响。
- 敌弹位于补给与烟尘上方的视觉层，维持危险提示优先级；尺寸和视觉外框不改变逻辑碰撞半径。
- 小屏上的尖弹使用略大的轮廓与更宽色芯，补给箱箭纹加粗；玩家中心判定点采用象牙白实心点与深色外圈，放在机身和补给之上、敌弹之下，外圈半径为 6 个逻辑单位。
- 高爆航弹以扩散冲击波清除弹幕；命中、爆炸使用火焰、碎片与烟尘。
- 移动时战机轻微压翼，螺旋桨持续旋转，僚机保持编队。
- 应急装甲以简洁的装甲指示表现，避免科幻能量罩。
- 不使用像素放大或 CRT 扫描线；reduced-motion 下减少装饰晃动、受击闪烁和震屏。

### 字体与界面

使用本地窄体英文与清晰中文，突出任务编号、仪表、作战日志和前线机型档案。深海军蓝面板搭配亮色文字与黄铜按钮，机库与手册提供战场识别图例。保持原有窗口适配，不能以滚动或裁切操作按钮容纳内容。

战斗计分栏的背景在逻辑纵坐标 80 前渐隐到透明，手机压缩积分区的标签与间距；文字使用阴影保持可读。波次横幅两侧渐隐，含文字和阴影的整体不透明度为 60%，中心底色叠加后的不透明度不超过 27%，让字形下也能透出来袭敌弹。首领栏使用半透明底色，尺寸随战场缩放且底边保持在逻辑纵坐标 130 以内。浏览器测试用真实敌弹检查顶栏、横幅背景及字形遮罩后的像素差异，同时检查判定点像素与首领栏位置；窗口改变后等待至少两帧再取证。

手册采用双列说明与图例，按窗口高度压缩留白与重复导语，保留清晰文字和至少 44px 高的主按钮；高度不超过 380px 的横屏将图例改为单行。适配测试同时检查弹窗内无滚动、按钮完整可见；横幅测试直接从机库创建静态战斗，避免开局计时器干扰，验证普通／首领横幅确实出现且遮罩下敌弹仍可见，并以移除敌弹后的同位置像素为对照，防止把亮色文字误当成敌弹。

## 需要持续保留的体验约束

- 战斗逻辑保持 480 × 760 坐标；模型尺寸、压翼与场景高度不改变玩法数值或碰撞判定。
- 暂停、强化、结算和机库在电脑与手机窗口内完整可见。
- 模型、字体和其他运行资产本地提供，声音使用 Web Audio 合成。
- 模型修改同步保留 Blender 源文件、导出资源与建模脚本，详见 [Blender 模型流程](models.md)。
- `game/visual-style.ts` 定义识别色与模型映射；模型测试核对 Blender 输出与这些色值一致，浏览器视觉检查读取真实截图中的颜色，覆盖混合战斗、密集首领弹幕、手机与灰度识别。

相关规则参见 [游戏玩法](gameplay.md) 和 [功能清单](features.md)。
