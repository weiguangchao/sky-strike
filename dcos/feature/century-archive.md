# 百年舰机档案与双 Sol 验收

## 收录口径与当前边界

目标是一战至现代、各国实际服役的军用飞机型号，以及水面战舰和潜艇舰级。不收录从未服役的原型或取消项目；涂装、运营国和改型不简单重复计为一个新型号。国家分裂、合并、转让和跨国研制需要在后续资料中分别记录。

**全球完整目录尚未建立，当前不是“所有型号已完成”。** 手册“历史图鉴”页明确显示持续补录。当前汇总 168 条资料：既有历史舰库 148 条，加上新增飞机 12 型、潜艇 8 级。既有 148 条中包含代表舰、同级姊妹舰和改装分组，不能宣传为 148 个不同舰级；美国 82 个分组也沿用原来的范围说明。

后续仍须逐国、逐时期核对服役名录，补充未覆盖的战斗机、轰炸机、运输机、教练机、侦察／巡逻机和各类水面舰、潜艇。当前第一批不构成穷尽的全球型号清单，待收录总数也不预设虚构数字。

后续型号的来源与未解决事项记录在[全球服役目录补录](inventory/README.md)。研究记录与运行时模型分开，尚未建模的资料不增加手册条目数或通过数。

## 手册行为

- 手册统一为“操作／作战单位／战役／历史图鉴”四个页签。原“舰库”和“百年”合并为历史图鉴，168条资料共用筛选、预览、史料与评分入口；不增加现代飞机或潜艇的战斗数值。
- 按国家／海军、飞机／水面舰／潜艇及六种水面舰种、外观年代筛选，支持直接选择、前后循环翻页和空结果。国家沿用原舰库海军口径，新飞机／潜艇采用设计来源国家；不声称已列出所有运营国。
- 使用同一个 192×120 像素 Canvas 2D 预览画布，查看条目才加载本地 PNG 精灵。切换页签、条目、筛选或关闭手册后，迟到的下载不得替换当前预览。失败提供重试，返回操作始终可用。
- 显示逐模型的真实双 Sol 状态；加载成功与评审通过是两件独立的事。未获两份合格评分的草稿可以预览，但不算验收通过。
- 水面舰艇主按钮为“使用本舰”“下次出击使用”或“已选用 · 返回”，保留本机存储与出击锁定外观；独立的“资料说明”按钮可查看史料。飞机与潜艇主按钮为“资料说明”，只供浏览。
- “资料说明”在同一手册内显示完整口径说明、主要史料及补充来源；支持触摸与键盘，打开后焦点进入说明标题，“返回图鉴”恢复该条模型。关闭手册仍使用右上角关闭按钮，不依赖鼠标悬停读取 `title`。
- 桌面和手机均不能产生页面或弹窗滚动；较矮横屏使用紧凑布局。改变窗口后至少等待两帧再做像素或布局检查。

## 建模与版本

- [build_archive.py](../../scripts/blender/build_archive.py) 使用 Blender Python API 生成各型号的主翼、机身、座舱、尾翼、支柱、进气口、喷口，或艇体、围壳、潜望镜、潜舵、推进器及甲板炮。
- [archive-profiles.ts](../../game/archive-profiles.ts) 分别保存20个型号的机身／艇体截面、垂尾／围壳侧轮廓与附件布局，经条目定义一并写入 Blender 输入。主翼使用有厚度的连续翼型，中央翼段闭合，翼根进入机身；双翼机独立定义下翼翼展、翼弦、错列与支柱跨数。主翼中心站位在输入中显式写为X=0，导出器不再移动翼根点来闭合中央段，避免改变作者的后掠角。零式座舱框沿实际玻璃表面铺设，喷气机有独立背脊、进气道与发动机舱轮廓。
- 潜艇分别定义船型／圆钝艏、舷侧外壳、甲板舷弧和开放或封闭围壳；自由进水上层外壳进入压力艇体。VII C 保留双舵和双轴布局，其他旧艇使用各自艉舵布局；现代艇使用十字／X舵。212A与苍龙的前水平舵安装在围壳上且根部接入实体；弗吉尼亚仅表现公开的泵喷外导管及支撑。
- 所有飞机的翼角统一使用度数，按实际半翼展换算；下反角为负数，不再把归一化翼尖高度当作角度。Camel 下翼约5°、上翼平直并保留中央后缘观察切口；Camel 上下翼均按8.53米翼展、1.372米翼弦制作，中央翼间距约1.524米、错列约0.457米；SPAD 上下翼平直；Spitfire 主翼约6°；P-51D 约5°；A6M5 约5.7°；MiG-21PF 约−2°；F-86A 主翼约3°、平尾约10°。F-16A 主翼平直、主翼前缘约40°而后缘平直，平尾前缘约40°、下反约10°；主翼面板按30英尺，早期平尾全展按18英尺0.34英寸，均区别于含导弹的总翼展。F-86A 后掠使用四分之一弦线约35°的口径，不能误作前缘角。
- 主翼平面轮廓校准到 Spitfire 约22.48平方米／根弦2.54米、P-51D 约21.9平方米、A6M5 约21.3平方米、F-86A 约26.75平方米、MiG-21PF 约23平方米。MiG 使用截梢三角翼，根弦约5.97米、翼尖弦约0.46米，并保留小型翼刀。测试读取实际导出网格量测面积、根弦／翼尖弦和翼角；P-51D主翼前缘按NACA约3°35′，A6M5前缘及较宽平尾按TAIC剪影校准；Spitfire平尾翼展按原手册10英尺6英寸。面积检查累加真实上表面三角形，不用凸包填补边条翼凹部及中央观察切口；参考面积的中央段、边条及鸭翼口径须分别核对，不能将隐藏的中央接合段计作露出翼面。
- 尾翼独立校准：F-86A平尾按NACA表中全展约3.886米、总面积约3.25平方米和四分之一弦后掠34°35′；MiG-21PF采用更大后掠的截尖平尾及垂尾，具体平尾展长仍待原始型线进一步核对。F-16A垂尾顶部后缘延至全机最后点，喷口在其前方；不能把垂尾整体前移。阵风裸翼展约9.95米，与军方图含翼尖导弹10.9米区分，鸭翼前后缘分别后掠；鹰狮鸭翼有独立后掠和正上反，角度为低多边形外形近似，不宣称厂商精确测绘值。
- 1942年早期Gato甲板炮位于围壳后方，与VII C的前置炮分别配置；不把后期炮位前移混入早期模型。阵风固定加油探管安装在风挡前方右侧，按军方共用机体三视图校准短伸段及其与机身的接合。
- 进气口外壳、口缘和凹入内壁沿同一截面生成；Gripen 使用方圆过渡入口。旧艇甲板按艇体、舷弧和甲板宽度的纵向站位生成平面条带，甲板面覆盖艇体顶部，避免整块非共面多边形被艇体穿出。苍龙上部外壳保留公开10.3米深度与9.1米宽度的比例。
- 新增可编辑源库为 [century-archive.blend](../../assets/blender/century-archive.blend)，输入快照为 [century-archive.json](../../assets/blender/century-archive.json)。旧战斗模型源库保持独立。
- `npm run models:build:archive` 重建这 20 个 GLB、源库和导出清单，并更新版本指纹。`npm run models:build` 先重建旧库，再重建新增库。
- 版本指纹包含 GLB 字节、完整型号定义、所属 `.blend` 源文件和建模脚本的 SHA-256。更新任意一项都会使该版本的旧评分失效；同一源库发生变化时整库均需重评。指纹在 [archive-revisions.json](../../game/archive-revisions.json)，校验入口为 [model-audit.ts](../../scripts/model-audit.ts)。

## 两名 GPT Sol 的硬性验收条件

每个模型需要两个不同的 GPT Sol 评审任务，独立给出 0–10 的有限数值，**两者均至少 9.8**。评分绑定同一轮次、同一个版本；不能合并跨轮次的两个分数，不能以平均分达标，也不能以一份总分代替逐模型评分。后续轮次的低分不能回退使用旧高分。

评审检查历史识别特征、比例与实体几何、实际 GLB 四视图、可编辑来源、资源预算，以及真实手册预览。评审自行给分，不要求其承诺高分。发现问题先修复，再发起新的两个只读评审任务；不得自行补分。

原始结果记录评审任务 ID、实际模型名、日期、轮次及逐模型评分和意见，保存在 [model-reviews.json](../../game/model-reviews.json)。文件未记录评分时状态为待评审；版本失配为待重评；任一分数低于 9.8 为未达标。自动化只校验记录与版本一致性，不代替模型质量判断或证明外部身份。

无法评分时使用 `score: null` 并记录非空理由，不能伪造为0分或省略该次尝试。它只让对应模型保持待评，不影响其他模型的真实评分；新一轮明确未评分也不能回退使用该模型旧轮次的通过记录。

```sh
npm run models:audit
npm run models:audit -- --require-approved
```

第一条校验版本并输出通过／待评审／待重评／未达标数量；第二条只有全部 168 条均通过才返回成功。`--refresh` 仅刷新版本指纹，不生成或补齐任何评分。

## 验证与评审图

`npm run typecheck`、`npm test`、`npm run build` 检查类型、战斗回归、实际导出资源、不同型号的几何、翼面朝向、螺旋桨／潜舵／推进器，以及评分门槛与失效规则。真实GLB检查还覆盖翼根与机身的体积接合、连续中央翼段、现代艇圆钝艏截面、212A／苍龙围壳潜舵的接合，以及明确未评分记录的隔离与旧通过失效。

导出几何回归还量测主翼和平尾角度、主翼弦长／后掠／面积、截尖翼的有限翼尖弦、进气口口缘与导管的双轴接合，以及五级旧艇甲板在多个纵向与横向取样点覆盖艇体顶部。自动化结果不替代独立评审分数。

`npm run test:e2e` 包含 [archive.spec.ts](../../tests/browser/archive.spec.ts)，覆盖 20 个新增真实预览、四时期筛选、空结果、失败重试、迟到下载、手机与极矮横屏。该测试也从实际 PNG 生成每个新增型号的顶视和斜向二维视图，输出到 `test-results/` 的 `council-views/`，供两名评审读取；不把测试截图当成运行资源。

原启动库保持小于 2.5MB，旧历史资源保持小于 17MB，新增首批小于 4MB，合计小于 21MB；每个 GLB 小于 400KB。GLB 为离线源资产，生产包只发布按需加载的 PNG。精灵生成及校验见[模型与精灵流程](models.md)。

原始GLB四视图审阅工具仍为 `scripts/archive-views.ts`，不进入产品入口。二维迁移没有重写 GLB 或源模型评分。图鉴评分继续指向原始几何版本，不代表新 PNG 已获得独立评分；二维画面由像素与完整图鉴预览测试另行验证。
