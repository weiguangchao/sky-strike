## 手册行为

- 手册统一为“操作／作战单位／战役／历史图鉴”四个页签。原“舰库”和“百年”合并为历史图鉴，八国资料共用筛选、预览与史料入口；不增加现代飞机或潜艇的战斗数值。
- 按国家／海军、飞机／潜艇／航空母舰／巡洋舰／驱逐舰／战列舰的平级类别、外观年代筛选，支持直接选择、前后循环翻页和空结果。国家筛选同时包含已核实的服役国，同一型号／舰级共用一个代表模型；未核实的额外运营关系不加入。条目区分代表外观国家／年份和已核实服役国，不将某国某年外观冒充其他运营国改装。例如幻影2000C可作为共享家族的法国代表供已核实运营国筛选，但ROC使用的是2000-5；米格21PF代表也不把早期歼7改称PF。许可型号边界与重大重新设计见[身份依据](inventory/aircraft-type-boundaries.json)。
- 使用同一个 192×120 像素 Canvas 2D 预览画布，查看条目才加载本地 PNG 精灵。切换页签、条目、筛选或关闭手册后，迟到的下载不得替换当前预览。失败提供重试，返回操作始终可用。
- 图鉴不显示评审状态或数值评分，也不加载内部评分账本。真实逐模型评审及批准规则继续由离线账本和审计工具维护，图像加载成功不代表评审通过。
- 水面舰艇主按钮为“使用本舰”“下次出击使用”或“已选用 · 返回”，保留本机存储与出击锁定外观；独立的“资料说明”按钮可查看史料。飞机与潜艇主按钮为“资料说明”，只供浏览。
- “资料说明”在同一手册内显示完整口径说明、主要史料及补充来源；支持触摸与键盘，打开后焦点进入说明标题，“返回图鉴”恢复该条模型。关闭手册仍使用右上角关闭按钮，不依赖鼠标悬停读取 `title`。
- 桌面和手机均不能产生页面或弹窗滚动；较矮横屏使用紧凑布局。改变窗口后至少等待两帧再做像素或布局检查。

## 建模与版本

- [build_archive.py](../../scripts/blender/build_archive.py) 使用 Blender Python API 生成各型号的主翼、机身、座舱、尾翼、支柱、进气口、喷口，或艇体、围壳、潜望镜、潜舵、推进器及甲板炮。
- [archive-profiles.ts](../../game/archive-profiles.ts) 分别保存当前36个型号的机身／艇体截面、垂尾／围壳侧轮廓与附件布局，经条目定义一并写入 Blender 输入。主翼使用有厚度的连续翼型，中央翼段闭合，翼根进入机身；双翼机独立定义下翼翼展、翼弦、错列与支柱跨数。主翼中心站位在输入中显式写为X=0，导出器不再移动翼根点来闭合中央段，避免改变作者的后掠角。零式座舱框沿实际玻璃表面铺设，喷气机有独立背脊、进气道与发动机舱轮廓。
- 潜艇分别定义船型／圆钝艏、舷侧外壳、甲板舷弧和开放或封闭围壳；自由进水上层外壳进入压力艇体。VII C 保留双舵和双轴布局，其他旧艇使用各自艉舵布局；现代艇使用十字／X舵。212A与苍龙的前水平舵安装在围壳上且根部接入实体；弗吉尼亚仅表现公开的泵喷外导管及支撑。
- 所有飞机的翼角统一使用度数，按实际半翼展换算；下反角为负数，不再把归一化翼尖高度当作角度。Camel 下翼约5°、上翼平直并保留中央后缘观察切口；Camel 上下翼均按8.53米翼展、1.372米翼弦制作，中央翼间距约1.524米、错列约0.457米；SPAD 上下翼平直；Spitfire 主翼约6°；P-51D 约5°；A6M5 约5.7°；MiG-21PF 约−2°；F-86A 主翼约3°、平尾约10°。F-16A 主翼平直、主翼前缘约40°而后缘平直，平尾前缘约40°、下反约10°；主翼面板按30英尺，早期平尾全展按18英尺0.34英寸，均区别于含导弹的总翼展。F-86A 后掠使用四分之一弦线约35°的口径，不能误作前缘角。
- 主翼平面轮廓校准到 Spitfire 约22.48平方米／根弦2.54米、P-51D 约21.9平方米、A6M5 约21.3平方米、F-86A 约26.75平方米、MiG-21PF 约23平方米。MiG 使用截梢三角翼，根弦约5.97米、翼尖弦约0.46米，并保留小型翼刀。测试读取实际导出网格量测面积、根弦／翼尖弦和翼角；P-51D主翼前缘按NACA约3°35′，A6M5前缘及较宽平尾按TAIC剪影校准；Spitfire平尾翼展按原手册10英尺6英寸。面积检查累加真实上表面三角形，不用凸包填补边条翼凹部及中央观察切口；参考面积的中央段、边条及鸭翼口径须分别核对，不能将隐藏的中央接合段计作露出翼面。
- 尾翼独立校准：F-86A平尾按NACA表中全展约3.886米、总面积约3.25平方米和四分之一弦后掠34°35′；MiG-21PF采用更大后掠的截尖平尾及垂尾，具体平尾展长仍待原始型线进一步核对。F-16A垂尾顶部后缘延至全机最后点，喷口在其前方；不能把垂尾整体前移。阵风裸翼展约9.95米，与军方图含翼尖导弹10.9米区分，鸭翼前后缘分别后掠；鹰狮鸭翼有独立后掠和正上反，角度为低多边形外形近似，不宣称厂商精确测绘值。

- 进气口外壳、口缘和凹入内壁沿同一截面生成；Gripen 使用方圆过渡入口。旧艇甲板按艇体、舷弧和甲板宽度的纵向站位生成平面条带，甲板面覆盖艇体顶部，避免整块非共面多边形被艇体穿出。苍龙上部外壳保留公开10.3米深度与9.1米宽度的比例。
- 新增可编辑源库为 [century-archive.blend](../../assets/blender/century-archive.blend)，输入快照为 [century-archive.json](../../assets/blender/century-archive.json)。旧战斗模型源库保持独立。
- `npm run models:build:archive` 重建当前36个GLB、源库和导出清单；随后运行 `npm run sprites:build` 生成PNG并更新版本指纹。`npm run models:build` 先重建旧库，再重建新增库。
- 版本指纹覆盖当前全部176个载具，包含 GLB 字节、最终 PNG、完整型号定义、所属 `.blend` 源文件、建模脚本、共享几何生成器与精灵生成器的 SHA-256。更新任意一项都会使该版本的旧评分失效；同一源库发生变化时整库均需重评。指纹在 [archive-revisions.json](../../game/archive-revisions.json)，校验入口为 [model-audit.ts](../../scripts/model-audit.ts)。

## 三方 council 的硬性验收条件

按2026-11-17用户最新要求，三位固定评审为Claude Opus 5.5（high）、GPT Sol（xhigh）、Cursor Grok 4.7（xhigh），三个不同提供方须独立给出0–10的有限数值。**先由Grok总评及本批全部当前模型评分达到≥9.8，再启动GPT和Claude；三方总评和每个模型的评分均须≥9.8。恰好9.8可通过。** 这取代早期轮次的Grok严格大于9.8规则，历史真实分数与顺序保持原样。

评审同时检查实体建模、所示年份的可见识别结构、编辑来源、源几何四视图、最终PNG、资源预算和手册预览。所有分数必须来自同一轮、同一模型版本；不能跨轮拼分、取平均、四舍五入或把总分替代逐项评分。Grok未达标不能启动后两席；修改后重新冻结版本并从新的Grok首审开始，不自行补分。新增型号也须完成核实服役、实际建模、验证和三方评分，不能把目录文字当成已建模。

旧双Sol记录保存在 [model-reviews-legacy.json](model-reviews-legacy.json)，仅作历史记录，不能使重建后的模型通过。新版本的记录从空轮次开始。

原始结果记录评审任务 ID、实际提供方、模型名、推理设置、日期、轮次、实际总评及逐模型评分和意见，保存在 [model-reviews.json](../../game/model-reviews.json)。文件未记录评分时状态为待评审；版本失配为待重评；任一评审总评或逐模型分数<9.8为未达标。自动化只校验记录与版本一致性，不代替模型质量判断或证明外部身份。

无法评分时使用 `score: null` 并记录非空理由，不能伪造为0分或省略该次尝试。它只让对应模型保持待评，不影响其他模型的真实评分；新一轮明确未评分也不能回退使用该模型旧轮次的通过记录。

```sh
npm run models:audit
npm run models:audit -- --require-grok
npm run models:audit -- --require-approved
```

第一条校验版本并输出各状态数量及Grok门槛状态；`--require-grok`只在最新轮次Grok总评和全部当前模型评分都≥9.8时返回成功，供启动GPT／Claude前检查；`--require-approved`只有当前全部载具均完成三方验收才返回成功。前两轮并行评审记录作为历史保留，不改写其真实评分或执行顺序。`--refresh` 仅刷新版本指纹，不生成或补齐任何评分。
